# plan-check

대상: 방금 작성된 구현 계획. 코드는 수정하지 않는다. 검증은 `qa` 에이전트에 맡겨 계획 작성자와 분리한다.

## 검증 항목
1. **존재 확인**: 계획에 언급된 모든 파일·클래스·함수·필드·UI 요소를 열거하고, 각각 실제로 있는지 검색한다. 라인 번호가 있으면 해당 위치가 맞는지 확인한다.
2. **이벤트 겹침**: 새로 추가하는 이벤트·효과가 같은 시점에 발생하는 기존 이벤트와 겹치는지 확인한다 (예: 착지 처리 중 BIG_JUMP, 아이템 획득).
3. **config 규칙**: 새 수치가 `src/config/` 에 들어가는지, 코드에 매직넘버가 생기지 않는지.
4. **하위 호환**: 저장 데이터(`pup_up_save`)·DB 컬럼 변경 시 기존 데이터가 그대로 동작하는지.
5. **누락**: 사용자 요청의 각 항목이 계획에 모두 반영됐는지, 설치·실행 같은 사용자 수동 단계가 빠지지 않았는지.
6. **금지 사항**: 점프·착지 판정 등 건드리면 안 되는 로직이 계획에 포함되지 않았는지.

## 출력 형식
- 문제가 있는 항목만 "항목, 근거(file:line 또는 검색 결과), 제안" 으로 목록화한다.
- 문제가 없으면 "이상 없음" 과 확인한 항목 수를 한 줄로 쓴다.
- 확인하지 못한 항목은 숨기지 말고 "미확인" 으로 적는다.
