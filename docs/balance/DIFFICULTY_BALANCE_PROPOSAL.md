# 난이도 밸런스 제안서 — 안 떨어질개

> 작성: 2026-09-28 · 기준 문서: GAME_RULES, BALANCE_DESIGN, PROGRESSION_DESIGN, RETENTION_DESIGN
> 코드는 보지 못했으므로 수치는 **현재값 대비 배율(1.0 = 현재)** 로 적었습니다. 실제 상수에 곱해서 쓰시면 됩니다.

---

## 0. 한 줄 결론

**"화면 3구역 × 배치 간격"이 아니라 "점프 1회 성공률"을 기준으로 난이도를 설계하세요.**
모든 난이도 파라미터를 하나의 난이도 지수 `D`(0~1)에 묶고, 초반 10번의 착지는 거의 실패하지 않게 만든 뒤, 톱니 모양(긴장 → 휴식)으로 올립니다.

---

## 1. 지금 어려운 이유 (진단)

| # | 원인 | 왜 문제인가 |
|---|------|------------|
| 1 | **타이밍 변수가 2개** (구름 궤도 위치 + 방향 휠 진자) | 하이퍼 캐주얼은 "한 가지만 보면 되는" 게임입니다. 두 개의 독립된 움직임이 맞아떨어져야 성공하면 체감 난이도는 두 배가 아니라 **곱**으로 올라갑니다. (콤보 폐기 사유에도 이미 "진자가 인지 부하"라고 적혀 있습니다.) |
| 2 | **난이도 곡선이 없음** (GAME_RULES "난이도 증가 방식: 미구현") | 첫 점프부터 중반 난이도입니다. 신규 유저에게는 첫 판이 곧 이탈 지점이 됩니다. |
| 3 | **즉사 장애물이 너무 빨리 등장** (새떼 10점 ≈ 착지 5~6회, 약 20초) | 조작을 익히기도 전에 두 번째 위협이 추가됩니다. 게다가 새떼는 방어막으로 못 막습니다. |
| 4 | **착지 판정이 엄격** (하강 중 + 윗면만) | 규칙 자체는 맞지만, 여유 판정(코요테 타임 등)이 없으면 "분명 닿았는데 떨어졌다"는 억울함이 생깁니다. |
| 5 | **공간 기준 3구역** | 화면 영역으로 나누면 플레이어의 진행도(점수·시간)와 난이도가 따로 놉니다. 같은 구역이면 1판째 유저와 50판째 유저가 같은 난이도를 겪습니다. |

> 참고: GAME_RULES는 "가장 가까운 위쪽 구름으로 자동 점프", 다른 문서는 "방향 휠 진자"라고 적혀 있어 서로 다릅니다. 이 제안서는 **방향 휠이 현재 구현**이라고 보고 썼습니다.

## 2. 핵심 원리: 점프 1회 성공률 `p`

N번 연속 착지할 확률 = `p^N`. 이 한 줄이 밸런스 전체를 좌우합니다.

| 점프 1회 성공률 p | 10회 생존 | 20회 생존 | 50회 생존 | 체감 |
|---|---|---|---|---|
| 90% | 35% | 12% | 0.5% | 너무 어려움 (지금 추정) |
| 95% | 60% | 36% | 8% | 어려움 |
| 97% | 74% | 54% | 22% | 적당 |
| 99% | 90% | 82% | 61% | 쉬움 |

**목표 곡선** (신규 유저 기준):

| 구간 | 착지 수 | 목표 p | 의미 |
|---|---|---|---|
| 튜토리얼 | 1~10 | **99%+** | 규칙만 익힘, 실패는 거의 없음 |
| 워밍업 | 11~30 | 97% | 첫 "아깝다" 경험 |
| 본게임 | 31~70 | 95%→93% | 평균 유저의 사망 구간 |
| 고수 | 71+ | 92%→90% (하한) | 기록 경쟁 |

이렇게 하면 신규 유저 중앙값이 착지 20~30회(≈ 1분), 숙련자는 2~3분으로 GAME_CONCEPT의 "회차당 1~3분"과 맞습니다.
**요점: 지금 "어렵다"는 느낌은 대부분 p가 초반부터 90% 근처이기 때문일 가능성이 큽니다.**

## 3. 구조: 난이도 지수 `D` 하나로 모든 값 제어

```ts
// 예시 — src/config/difficultyConfig.ts (신규)
// landings: 이번 판 착지 횟수
function difficulty(landings: number): number {
  const base = Math.min(1, Math.max(0, (landings - 10) / 90)); // 10회까지 0, 100회에 1
  const eased = base * base * (3 - 2 * base);                  // smoothstep: 초반 완만, 후반 완만
  return eased;
}
// 각 파라미터 = lerp(쉬운값, 어려운값, D)
```

- 기준은 **점수가 아니라 착지 횟수**를 추천합니다. 점수는 스킵 점프로 튀기 때문에 난이도가 들쭉날쭉해집니다.
- 3구역 개념은 버리지 말고 **"구간 = D 범위"** 로 바꿔 쓰면 됩니다 (튜토리얼/워밍업/본게임/고수).

### 파라미터 표 (1.0 = 현재값)

| 파라미터 | D=0 (시작) | D=1 (최대) | 우선순위 | 비고 |
|---|---|---|---|---|
| 방향 휠 진자 속도 | **0.5** | 1.1 | ★★★ | 가장 큰 레버. 초반엔 느리게 |
| 구름 궤도 속도 | 0.5 | 1.2 | ★★★ | |
| 구름 궤도 반지름 | 0.4 | 1.1 | ★★ | 초반엔 거의 제자리에서 흔들리는 정도 |
| 구름 폭(착지면) | 1.4 | 0.85 | ★★★ | 폭이 성공률에 가장 직결 |
| 층간 간격 (평균 310px) | 0.85 | 1.1 | ★★ | 간격 바꾸면 HEIGHT_UNIT도 같이 확인 |
| 착지 판정 여유 (Y 허용) | 1.5 | 1.0 | ★★ | 끝까지 1.0 아래로 내리지 않음 |
| 새떼 스폰 간격 (8~15초) | 등장 안 함 | 0.7 | ★★ | |
| 번개 스폰 간격 (30~60초) | 등장 안 함 | 0.7 | ★ | |

**동시에 전부 올리지 마세요.** 한 구간에서는 1~2개만 올리고 나머지는 유지하는 편이 "새로운 도전"처럼 느껴집니다. 예:
- 워밍업: 진자 속도·궤도 속도만 오름
- 본게임: 구름 폭 감소 + 새떼 등장
- 고수: 궤도 반지름 확대 + 번개 등장 + 장애물 간격 단축

## 4. 톱니형 곡선 (긴장 → 휴식)

직선으로 계속 올리면 피로가 쌓입니다. **8~10회 착지마다 "쉼터 구름"** 을 넣으세요.

```
난이도
  │        /|      /|      /|
  │      /  |    /  |    /  |
  │    /    |  /    |  /    |
  │  /      |/      |/      |
  └────────────────────────────▶ 착지 수
         쉼터     쉼터     쉼터
```

- 쉼터 구름: 폭 넓음, 궤도 정지(또는 매우 느림), 장애물 없음, 코인/아이템 배치
- 쉼터 직후 D를 약 0.05 내렸다가 다시 올림
- RETENTION_DESIGN의 인-런 마일스톤 코인과 쉼터 위치를 맞추면 보상 타이밍과 휴식이 겹쳐 효과가 큽니다

## 5. 초반 완화 (가장 먼저 적용할 것)

1. **첫 5개 구름은 궤도 반지름 거의 0** — 이동 없이 살짝 흔들리기만. "탭하면 점프한다"만 배우게 합니다.
2. **진자 속도 50%로 시작**, 착지 10회까지 유지.
3. **장애물 해금 늦추기**: 새떼 10점 → **착지 25회(≈ 45~50점)**, 번개 30점 → **착지 50회**. 첫 등장 때는 1초 이상 경고 표시.
4. **코요테 타임 / 관대한 판정**: 구름 가장자리에서 발이 5~8px 벗어나도 착지 인정, 윗면 판정 두께를 살짝 두껍게. 플레이어는 거의 알아채지 못하지만 억울한 사망이 크게 줄어듭니다.
5. **첫 판 보험 (신규 유저 1~3판)**: 착지 5회 전에 떨어지면 자동으로 근처 구름에 한 번 올려 줌 (광고·다이아 없이).

## 6. 숨은 난이도 보정 (DDA)

하이퍼 캐주얼에서 흔히 쓰는 방식입니다. 유저에게 알리지 않습니다.

| 조건 | 보정 |
|---|---|
| 3판 연속 착지 10회 미만 사망 | 다음 판 D 시작값 -0.1, 진자 속도 ×0.9 |
| 최고기록 근처(90% 이상)에서 사망 반복 | 해당 구간 구름 폭 ×1.1 (최대 2판) |
| 최근 5판 평균이 최고기록의 150% 이상 | 보정 해제 |

- 보정은 **작게, 천천히**. 티가 나면 오히려 성취감을 깎습니다.
- 리더보드 공정성이 걱정되면 보정은 "착지 30회 미만 구간"에만 적용하세요.

## 7. 장애물 공정성 규칙

1. **위협은 동시에 하나만**: 새떼와 번개가 같은 5초 안에 겹치지 않게 전역 쿨다운.
2. **점프 중 기습 금지**: 새떼는 캐릭터가 착지해 있을 때 경고 → 등장. 점프 중에 새로 나타나 부딪히는 일은 없게.
3. **경고 시간 ≥ 1초**, 고수 구간에서도 0.7초 아래로 내리지 않음.
4. **새떼는 방어막으로 못 막는 즉사**라서 번개보다 위협이 큽니다. 둘 중 하나는 완화 권장: 방어막으로 새떼 1회 방어 허용, 또는 새떼 충돌 시 즉사 대신 "넉백 + 아래 구름으로 떨어짐".

## 8. 배치 방식: 공간 3분할 → "청크(패턴 조각)" 방식

- 구름 3~5개로 된 **패턴 조각을 미리 손으로 만들고**, 각 조각에 난이도 태그(1~5)를 붙입니다.
- 게임 중에는 현재 D에 맞는 태그의 조각 중 하나를 랜덤으로 이어 붙입니다.
- 장점: 어떤 조각이든 "도달 가능"이 검증된 상태라 **불가능한 배치가 생기지 않고**, 난이도 조절이 조각 단위로 쉬워집니다.
- 기존 "패턴1" 개념을 이 조각 시스템의 태그로 확장하면 됩니다.

**생성 시 검증 규칙 (랜덤 배치를 유지한다면 최소한 이것만):**
- 다음 구름이 착지 가능한 "시간 창"이 한 궤도 주기 안에 최소 X초 존재 (초반 1.0초, 후반 0.4초)
- 연속 2개 구름이 모두 최고 난이도 태그가 되지 않게

## 9. 업그레이드와의 관계 (P2W 방지)

영구 업그레이드(착지 판정 +20%, 자석 12초 등)는 사실상 D를 낮춥니다. 원칙:
- 업그레이드 전부 합쳐도 **p를 최대 +2%p** 정도만 올리도록 (예: 93% → 95%)
- 판정 확대는 "착지 판정 여유" 파라미터에 곱하되, 상한을 둠 (기본 대비 최대 1.2배)

---

## 10. 측정: 감이 아니라 숫자로 조정

Supabase에 판마다 아래만 기록해도 충분합니다.

| 필드 | 용도 |
|---|---|
| `landings`, `score`, `duration_ms` | 생존 곡선 |
| `death_cause` (추락/새떼/번개) | 어떤 요소가 과한지 |
| `death_D` (사망 시 난이도 지수) | 어느 구간이 벽인지 |
| `run_index` (이 유저의 몇 번째 판) | 신규 유저 이탈 확인 |

**목표 지표 (신규 유저 첫 5판 기준):**
- 착지 5회 전 사망 비율 **< 15%**
- 첫 판 생존 시간 중앙값 **≥ 30초**
- 사망 원인 중 장애물 비율 **< 30%** (추락이 주가 되어야 "내 실수"로 느껴짐)
- 착지 횟수별 사망 히스토그램에 **뾰족한 벽이 없을 것** (있으면 그 구간 파라미터를 낮춤)

## 11. 적용 순서 (추천)

1. **진자 속도 초반 50% + 첫 5개 구름 정지 + 장애물 해금 늦추기** — 코드 수정 최소, 효과 최대
2. 판정 여유(코요테 타임) 추가
3. `difficultyConfig.ts` 만들어 D 기반으로 파라미터 통합
4. 쉼터 구름 + 인-런 마일스톤 연동
5. 로그 수집 → 지표 보고 수치 조정
6. 청크 시스템, DDA (출시 후 데이터 보며)

1~2번만 적용해도 "어렵다"는 체감은 크게 줄어들 것으로 예상합니다.
